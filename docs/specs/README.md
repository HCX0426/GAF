# specs/ 设计文档 spec 索引

本目录用于存放**跨设计文档的 spec 索引和依赖关系图**，以及进行中/已归档的 spec 文件。

## 目录结构

```
specs/
├── README.md              # 本文件（spec 编写规范）
├── dependency-graph.md    # Spec 依赖关系图（auto-generated by spec_dependency_graph.py）
├── active/                # 进行中 spec（完成后移到 archived/YYYY-MM/）
├── archived/              # 已完成按月归档
│   └── YYYY-MM/
└── legacy-trae/           # 原 .trae/specs/ 合并 (spec-2026-07-26-trae-specs-plans-merge)
    └── YYYY-MM-DD-specNN-*.md
```

## 目录职责区分

| 目录 | 用途 | 管理方式 |
|------|------|---------|
| `docs/business/` / `docs/architecture/` | 设计文档（架构、机制、方案） | AI 维护 |
| `docs/specs/` | 跨设计文档的 spec 索引/依赖图 + 进行中/已归档 spec | AI 维护 + 脚本自动生成 |
| `docs/standards/` | 编码/API/测试规范 | AI 维护 |
| `docs/archive/` | 归档文件 (技术债/健康报告/已完成功能等) | AI 维护 |
| `docs/specs/legacy-trae/` | 原 `.trae/specs/` 历史 spec (2026-07-26 合并) | AI 维护，只读历史 |

## 添加新 spec 索引

当一个设计文档引用或依赖其他设计文档时，在 `dependency-graph.md` 描述依赖关系（由 `scripts/governance/spec_dependency_graph.py` 自动生成），便于 AI 快速定位影响范围。

## spec 生命周期

1. **创建**：新 spec 放 `specs/archived/<YYYY-MM>/<YYYY-MM-DD>-<slug>.md` (完成后直接归档)
2. **实施**：实施计划放 `docs/specs/archived/<YYYY-MM>/<YYYY-MM-DD>-<slug>.md` (plan 已合并到 specs)
3. **完成**：spec 移到 `specs/archived/YYYY-MM/`（plan 已合并到 specs，不再单独维护）

## 注意

- 单个设计文档放 `business/` 或 `architecture/`，不要放本目录
- ~~TRAE 工具生成的 `spec{N}-td{M}-{slug}.md` 文件由工具自动写入 `.trae/specs/`，不要手动移动~~ — 2026-07-26 spec-2026-07-26-trae-specs-plans-merge 已将 `.trae/specs/` 内容合并到 `specs/legacy-trae/`, `.trae/specs/` 已删除
- `dependency-graph.md` 是 auto-generated，不要手动编辑
