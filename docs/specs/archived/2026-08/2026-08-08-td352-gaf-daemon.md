## 1. 问题描述

### 1.1 现状

GAF 服务启动和守护完全依赖 `scripts/gaf_services.ps1` PowerShell 脚本。该脚本通过 `Start-Process` 启动各服务进程，仅提供 `start/stop/restart/status` 命令，**无看门狗自动重启机制**。

### 1.2 具体问题

| 问题 | 描述 | 影响 |
|------|------|------|
| **无自动恢复** | Celery Worker / Backend / Agent 崩溃后无自动拉起 | PENDING 任务永久堆积，需人工 `Stop-GafService` + `start` |
| **PowerShell 依赖** | 服务管理完全依赖 PowerShell，跨平台迁移困难 | 无法在 Linux 环境部署 |
| **启动顺序不严格** | 脚本按顺序启动但不验证上游服务就绪后才启动下游 | 前端启动时 Backend 可能未就绪，出现 502 |
| **状态检测不完整** | 仅检测端口监听，不检测进程健康度（如内存泄漏、响应超时） | 端口监听正常但服务已死锁，误判为正常 |
| **Windows 重启不恢复** | 系统重启后服务不会自动恢复 | 需手动执行 `gaf_services.ps1 start` |

### 1.3 根因

服务管理无独立的守护进程，依赖一次性 PowerShell 脚本，脚本退出后无人看守。

## 2. 修复方案

### 2.1 架构概览

开发 `scripts/gaf_daemon.py` Python 守护进程，替代 PowerShell 脚本的服务管理职责：

```
┌─────────────────────────────────────────────────┐
│              gaf_daemon.py                       │
│  ┌──────────┐  ┌──────────┐  ┌────────────────┐ │
│  │ CLI 命令  │  │ 启动器    │  │ 看门狗循环      │ │
│  │ start/   │→ │ 按顺序    │→ │ poll() 检查     │ │
│  │ stop/    │  │ 启动服务  │  │ 崩溃自动重启    │ │
│  │ status   │  │ 验证就绪  │  │ 30s 周期       │ │
│  └──────────┘  └──────────┘  └────────────────┘ │
│  ┌──────────┐  ┌──────────┐                      │
│  │ 信号处理  │  │ 日志管理  │                      │
│  │ SIGINT → │  │ stdout +  │                      │
│  │ 优雅关闭  │  │ 文件日志  │                      │
│  └──────────┘  └──────────┘                      │
└─────────────────────────────────────────────────┘
         │               │               │
         ▼               ▼               ▼
   ┌──────────┐   ┌──────────┐   ┌──────────┐
   │  Redis    │   │ Backend  │   │  Agent   │
   │  (6379)   │   │ (daphne) │   │ (python) │
   └──────────┘   └──────────┘   └──────────┘
                        │
                  ┌─────┴─────┐
                  ▼           ▼
            ┌──────────┐ ┌──────────┐
            │ Celery    │ │ Frontend │
            │ Worker    │ │ (Vite)   │
            └──────────┘ └──────────┘
```

### 2.2 运行模式

| 模式 | 命令 | 说明 |
|------|------|------|
| **daemon** | `python scripts/gaf_daemon.py daemon` | 启动所有服务 + 看门狗循环 + 信号处理 |
| **start** | `python scripts/gaf_daemon.py start` | 启动所有服务，然后退出（无看门狗） |
| **stop** | `python scripts/gaf_daemon.py stop` | 按反向顺序停止所有服务 |
| **restart** | `python scripts/gaf_daemon.py restart` | stop + start |
| **status** | `python scripts/gaf_daemon.py status` | 显示各服务进程状态 |
| **monitor** | `python scripts/gaf_daemon.py monitor` | 仅启动看门狗，不启动服务（用于外部启动的场景） |

### 2.3 服务定义

```python
SERVICES = {
    "redis": {
        "cmd": [REDIS_SERVER_EXE],
        "cwd": os.path.dirname(REDIS_SERVER_EXE),
        "port": REDIS_PORT,
        "verify": "redis_ping",  # 验证方式
        "depends_on": [],  # 依赖的上游服务
        "delay": 2.0,      # 启动后等待时间
    },
    "backend": {
        "cmd": [PYTHON_EXE, "-m", "daphne", "config.asgi:application",
                "-b", "0.0.0.0", "-p", str(BACKEND_PORT)],
        "cwd": BACKEND_DIR,
        "port": BACKEND_PORT,
        "verify": "port_listen",
        "depends_on": ["redis"],
        "delay": 5.0,
    },
    "celery_worker": {  # 仅 GAF_CELERY_MODE=celery 时启用
        "cmd": [PYTHON_EXE, "-m", "celery", "-A", "config", "worker",
                "--loglevel=INFO", "--pool=threads", "--concurrency=4"],
        "cwd": BACKEND_DIR,
        "port": None,
        "verify": "celery_ping",
        "depends_on": ["redis", "backend"],
        "delay": 3.0,
    },
    "celery_beat": {  # 仅 GAF_CELERY_MODE=celery 时启用
        "cmd": [PYTHON_EXE, "-m", "celery", "-A", "config", "beat",
                "--loglevel=INFO"],
        "cwd": BACKEND_DIR,
        "port": None,
        "verify": "process",
        "depends_on": ["redis", "backend"],
        "delay": 1.0,
    },
    "agent": {
        "cmd": [PYTHON_EXE, "-m", "src", "--log-level", "INFO"],
        "cwd": AGENT_DIR,
        "port": None,
        "verify": "agent_log",
        "depends_on": ["backend"],
        "delay": 5.0,
    },
    "frontend": {
        "cmd": [NPM_EXE, "run", "dev"],
        "cwd": FRONTEND_DIR,
        "port": FRONTEND_PORT,
        "verify": "port_listen",
        "depends_on": ["backend"],
        "delay": 3.0,
    },
}
```

### 2.4 启动顺序

```
eager 模式 (开发): Redis → Backend → Agent → Frontend
celery 模式 (生产): Redis → Backend → Worker → Beat → Agent → Frontend
```

每个服务启动后等待验证通过（端口监听/Redis PING/日志匹配），再启动下一个。

### 2.5 看门狗循环

- **周期**: 每 15 秒检查一次
- **检查方式**: `process.poll()` 返回非 None 表示进程已退出
- **重启策略**: 崩溃后立即重启，最多重试 3 次/30 分钟
- **日志**: 每次重启记录到 daemon 日志（时间戳 + 服务名 + 退出码 + 重启次数）
- **停止条件**: 连续 3 次在 30 分钟内崩溃 → 停止自动重启（告警通知）

### 2.6 停止顺序

```
反向停止: Frontend → Agent → Beat → Worker → Backend → Redis
```

每个服务先 `process.terminate()`（等待 5 秒），超时则 `process.kill()`。

### 2.7 信号处理

| 信号 | 行为 |
|------|------|
| SIGINT (Ctrl+C) | 优雅关闭所有服务后退出 |
| SIGTERM | 优雅关闭所有服务后退出 |

### 2.8 配置文件

守护进程配置从 `.env` 文件读取：

```ini
# 以下配置 gaf_daemon.py 自动读取
REDIS_URL=redis://localhost:6379/0
BACKEND_PORT=8000
FRONTEND_PORT=5173
GAF_CELERY_MODE=eager
```

### 2.9 与 gaf_services.ps1 的关系

| 维度 | 改造前 | 改造后 |
|------|--------|--------|
| 启动方式 | `gaf_services.ps1 start` | `gaf_daemon.py daemon` 或 `gaf_services.ps1 start` |
| 看门狗 | 无 | `gaf_daemon.py daemon` 内置 |
| 进程管理 | PowerShell `Start-Process` | Python `subprocess.Popen` |
| 状态检测 | 端口监听 | 端口 + 进程存活 + 业务验证 |
| 日志 | 独立文件 | 统一 + daemon 自身日志 |

`gaf_services.ps1` 的 `start` 命令改为调用 `gaf_daemon.py daemon`，保持向后兼容。

## 7. 已知限制

- 看门狗周期固定 15 秒，无法自动调整
- 连续崩溃 3 次/30 分钟后停止自动重启，需人工介入
- 不支持跨机器进程管理（当前均为单机部署）
- daemon 模式前台运行，无后台 `--detach` 模式（当前 Windows 开发环境下不需要）
- 不支持 Windows 服务注册（可选，后续可加）
