### ⑩ N111 命令超时主动中止 Y/N 矩阵（必填，M1.A 闭环加项）

> **触发条件**（任意一条即触发）:
> - AI 跑 `pytest` / `migrate` / `pip install` / `npm install` 等长时命令
> - 命令跑 > 预期时间 (按 5 段判别: 0-30s/30s-2min/2-5min/5-15min/>15min)
> - 默认 blocking=true 但 0 输出超 2min
> - 用户反馈 "ai运行终端命令时，要是时间超过预期时间要会主动结束那次的命令看报错"

**Y/N 检查表**:
| # | 检查项 | Y/N | 验证命令 |
|:-:|--------|:---:|----------|
| 1 | 跑了 > 预期时间 (按命令类型基线 §5.3 判别) | | `Get-Date` 与命令起始时间对比 |
| 2 | CheckCommandStatus 查过最新输出 (不带 wait_ms) | | `CheckCommandStatus` 工具调用 |
| 3 | 输出为 0 行 + 超预期 → 主动 StopCommand 杀 | | `StopCommand` 工具调用 |
| 4 | 主动结束后报 "命令疑似卡死, 已结束, 请确认" (N101 状态诚实) | | 文本输出 |
| 5 | 长命令改用 `blocking=false` + `wait_ms_before_async=10000` 异步 | | 参数配置 |
| 6 | 杀命令后**换替代方案继续** (不放弃任务目标, 见 §3.5 换方式策略表) | | 文本输出证明换方式 |

**AI 必做**:
- ✅ 5 段超时判别: 0-30s (短) / 30s-2min (中) / 2-5min (中长) / 5-15min (长) / >15min (超长)
- ✅ 命令类型预期基线 (10+ 类: pytest/lint/migrate/sync/pip/npm 各自有标准时间)
- ✅ 6 步超时应对: 超时 → CheckCommandStatus 查 → 0 输出 StopCommand → 报原因 → 异步 → **换方式继续**
- ✅ 主动结束 ≠ 失败 = AI 成熟标志 (N111 §3.2)
- ✅ 杀命令后必换方式继续 (不放弃任务目标, 见 §3.5)
- ❌ NEVER 命令跑超 2min 0 输出仍傻等
- ❌ NEVER 跑长命令不设预期时间
- ❌ NEVER 等到 Trae session 5min 强制 timeout (AI 应主动提前)
- ❌ NEVER 主动结束命令后不报原因 (违反 N101 状态诚实)
- ❌ NEVER 杀命令后直接放弃任务目标 (必须换方式继续)
- ❌ NEVER inline 拼路径 (违反 N106)
- ❌ NEVER 跑通 sync 工具就声称"路径正确" (违反 N106)

**§3.5 换方式策略表** (杀命令后必选一种继续):

| 策略 | 适用场景 | 操作 |
|:----:|---------|------|
| **拆分** | 长命令跑全量 (pytest 全套 / npm build) | 拆成 per-app / per-module 分段跑, 缩小范围定位卡点 |
| **异步** | 命令本身需长跑 (dev server / celery) | `blocking=false` + `wait_ms_before_async=10000`, 后台跑 + 定期 CheckCommandStatus |
| **子 agent** | 命令输出过大 / 需独立调试 | `Task` 工具分发, 保护主 context window |
| **降级** | 全量跑不通但急需验证 | 跑关键子集 + 标注"降级验证, 全量待补" |
| **换工具** | RunCommand 卡死 / 输出截断 | Write 临时 .py/.ps1 脚本 → RunCommand 跑脚本 (绕过 inline 限制) |
| **根因修复** | 命令报错 (非卡死) | 先根因分析 (§2.0), 能当场修则修, 不能则登记 tech-debt (§4.8) |

#### N127 i18n 接入模式 (参考子段, 无独立 Y/N 矩阵)

**i18n 接入模式 (可复用)**:
